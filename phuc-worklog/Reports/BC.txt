Những phần đã hoàn thành
- Thiết lập DynamoDB Local bằng Docker Compose, Backend Python chạy qua AWS SAM Local.
- Triển khai các API:
  - GET /health
  - GET /events
  - GET /events/{eventId}
  - POST /events/{eventId}/registrations
  - GET /registrations/{registrationId}
- Kiểm tra dữ liệu đăng ký; chuẩn hóa email để chống trùng trong cùng sự kiện.
- Dùng DynamoDB transaction để giảm chỗ, tạo đăng ký và tạo khóa chống trùng cùng nhau; tránh vượt sức chứa khi nhiều request đồng thời.
- Sử dụng UUID v4 cho mã đăng ký và chỉ trả các trường theo API contract.
- Frontend gọi Backend cho toàn bộ luồng người tham dự, giữ nguyên thiết kế hiện có.
- Chọn chế độ api hoặc mock bằng biến môi trường. Chế độ API hiển thị lỗi Backend, không tự chuyển sang localStorage.
- Cập nhật README, API contract, data model và hướng dẫn kiểm tra.
- Seed dữ liệu theo cách không ghi đè các bản ghi đã tồn tại.

Nhóm file thay đổi chính
- backend/lambda/: xử lý request, cấu hình, nghiệp vụ và truy cập DynamoDB.
- backend/template.yaml, backend/compose.yaml: môi trường chạy local.
- backend/dynamodb_setup/, backend/tools/: khởi tạo dữ liệu và công cụ kiểm tra.
- frontend/src/services/: HTTP service và lựa chọn chế độ mock/API.
- frontend/src/pages/, hooks và types: tích hợp dữ liệu, đăng ký và xử lý trạng thái.
- tests/backend/, tests/frontend/: kiểm thử Backend và trình duyệt.
- README và docs/: cập nhật cách chạy, contract và mô hình dữ liệu.
Giới hạn hiện tại: hệ thống mới chạy local; chưa triển khai AWS, Admin Dashboard, email xác nhận hoặc đăng nhập. Endpoint kết quả chưa có xác thực; UUID khó đoán nhưng người có đường dẫn vẫn đọc được thông tin. Chưa có cơ chế idempotency để khôi phục kết quả khi client mất kết nối ngay sau khi đăng ký thành công.

Theo cập nhật của bạn, Codex đã hoàn thành bước API đăng ký và tích hợp Frontend. Dự án hiện đã đi từ prototype dùng mock data sang luồng đăng ký chạy với Backend và DynamoDB Local. Tôi chưa có báo cáo kiểm thử của bước mới này, nên phần “đã hoàn thành” dưới đây là theo xác nhận của bạn; kết quả từng ca kiểm thử cần đối chiếu với báo cáo Codex.

cách test
1. Khởi động Backend trong Terminal 1. Nếu SAM đang chạy, nhấn Ctrl+C trước để nạp các route mới.
   $env:SAM_CLI_TELEMETRY='0'
   $env:AWS_ACCESS_KEY_ID='local'
   $env:AWS_SECRET_ACCESS_KEY='local'
   $env:AWS_DEFAULT_REGION='us-east-1'
   $env:AWS_EC2_METADATA_DISABLED='true'
   
   docker compose -f backend/compose.yaml up -d dynamodb
   sam build --use-container --template-file backend/template.yaml
   
   sam local start-api --template .aws-sam/build/template.yaml --env-vars backend/env.local.example.json --docker-network fcaj-event-workshop-local --host 127.0.0.1 --port 3001 --warm-containers LAZY
   Giữ terminal này chạy. Log request và lỗi Python hiện tại đây. Lần gọi đầu có thể mất vài chục giây.
2. Khởi động Frontend trong Terminal 2.
   Kiểm tra frontend/.env.local có:
   VITE_DATA_MODE=api
   VITE_API_BASE_URL=http://127.0.0.1:3001
   Sau đó chạy:
   npm --prefix frontend run dev -- --port 5173 --strictPort
   Mở http://localhost:5173/events. Nếu sửa .env.local, cần restart Vite.
3. Kiểm tra thủ công theo bảng sau.
   Tình huống	Cách thử	Kết quả mong đợi
   Đăng ký thành công	Chọn sự kiện còn chỗ, nhập tên và email mới	Sang trang kết quả, có mã đăng ký
   Lưu kết quả	Nhấn F5 tại trang kết quả	Vẫn đọc được thông tin
   Giảm chỗ	Quay lại chi tiết sự kiện	Giảm đúng một chỗ
   Email trùng	Đăng ký lại cùng sự kiện với email vừa dùng, đổi hoa/thường	Báo trùng, không giảm thêm chỗ
   Email ở sự kiện khác	Dùng email đó đăng ký sự kiện còn chỗ khác	Đăng ký được
   Validation	Để trống tên, nhập email sai hoặc số điện thoại dài hơn 32 ký tự	Báo lỗi tại trường tương ứng
   Gửi liên tiếp	Bấm nhanh nút xác nhận nhiều lần	Hiện đang gửi, chỉ tạo một đăng ký
   Hết chỗ	Mở /events/cv-dung-nang-luc/register	Chặn đăng ký
   Đã kết thúc	Mở /events/nhiep-anh-ke-chuyen/register	Chặn đăng ký
   ID sai	Mở /events/no-such-event	Báo không tìm thấy
   Tìm kiếm/lọc	Kết hợp tên, danh mục và trạng thái	Danh sách thay đổi đúng; xóa lọc phục hồi danh sách
   
   
   Dùng email riêng cho kiểm thử, ví dụ test01@example.com. Các đăng ký này sẽ được lưu thật trong DynamoDB Local.
4. Thử lỗi database.
   Mở sẵn form đăng ký, sau đó trong Terminal 3 chạy:
   docker compose -f backend/compose.yaml stop dynamodb
   Bấm xác nhận trên form. Kết quả mong đợi: báo database chưa sẵn sàng và giữ nguyên dữ liệu đã nhập.
   Bật DB lại rồi thử gửi lại:
   docker compose -f backend/compose.yaml start dynamodb
   Xem log DB khi cần:
   docker compose -f backend/compose.yaml logs -f dynamodb
5. Chạy kiểm tra tự động trong Terminal 3.
   # Kiểm tra các API đọc, không ghi dữ liệu
   python backend/tools/check_api.py --base-url http://127.0.0.1:3001
   
   # Unit test Backend
   docker compose -f backend/compose.yaml run --rm tools -m unittest discover -s tests/backend -v
   
   # Frontend
   npm --prefix frontend run build
   npm --prefix frontend run lint
   Mong đợi: smoke test in "checks": "passed"; unittest có 26 test đạt, 2 integration test được skip; build/lint thành công. Hai cảnh báo Fast Refresh hiện có không làm lint thất bại.
Để kiểm tra transaction đồng thời và tranh chỗ cuối, hãy dùng bảng test riêng. Sau khi thử xong luồng chính, Ctrl+C SAM trong Terminal 1 rồi chạy ngay trong terminal đó:
$test = python backend/tools/new_test_environment.py | ConvertFrom-Json

docker compose -f backend/compose.yaml run --rm -e RUN_DYNAMODB_INTEGRATION=1 -e DYNAMODB_ENDPOINT=http://fcaj-dynamodb-local:8000 -e "DYNAMODB_TABLE=$($test.table)" tools -m unittest discover -s tests/backend -p test_registration_integration.py -v

sam local start-api --template .aws-sam/build/template.yaml --env-vars $test.envFile --docker-network fcaj-event-workshop-local --host 127.0.0.1 --port 3002 --warm-containers LAZY
Trong Terminal 3:
python backend/tools/check_registration_api.py --base-url http://127.0.0.1:3002
Mong đợi: 2 integration test đạt, smoke test báo "checks": "passed" và "lastSeatWinners": 1. Các kiểm tra này tạo dữ liệu trong bảng test riêng và giữ lại bảng sau khi chạy.
